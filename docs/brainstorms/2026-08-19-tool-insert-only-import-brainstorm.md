# 爬取数据仅新增导入

## What We're Building

调整 `tool/` 下的归档与 MySQL 导入工具，让新记录优先使用 API 返回的数据库原始字段，无法取得的字段才采用明确记录在报告中的推断值。数据库中已存在的记录一律保留；同一业务实体的资料变化只记录为“已保留差异”，不会更新密码、会话、用户资料、主题或帖子。

已有父记录不会阻止缺失子记录的补入，例如主题已存在时仍可新增缺失楼层，楼层已存在时仍可新增缺失楼中楼。真正的唯一键身份碰撞仍作为冲突停止相关子记录写入。

## Why This Approach

选择“只补新增数据”是因为它最符合本地已有数据不可被爬取快照覆盖的边界。相较于当前实现，它避免把可见回复数误当数据库计数、避免使用较旧的主题列表摘要，也消除重复导入时重置已有用户密码的副作用。

## Key Decisions

- 原始详情优先：主题使用 `thread.raw`，帖子和楼中楼使用各自 `raw`。
- 保留源计数：`threads.reply` 和 `posts.lzl` 不再由当前可见项目数重算。
- 附件精确归档：后续爬取通过 `attachinfo` 保存完整附件原始字段；旧归档缺字段时继续推断并在报告中标明。
- 仅新增：已有相同身份的行不更新；内容不同记为 preserved，不视作失败。
- 身份冲突保护：同一 `fid` 指向不同主题/楼层等情况仍记为 conflict。
- 子记录可补齐：父行 preserved/skipped 时继续尝试插入缺失子行。

## Open Questions

- 无。用户已确认采用仅新增策略。
